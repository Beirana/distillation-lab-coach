# Artifact Map

When explaining a file, first identify its stage, then state what it supports and what it cannot prove by itself.

| File or directory | Meaning | Supports | Does not prove by itself |
|---|---|---|---|
| `configs/course.json` | Experiment contract for models, data version, split sizes, seed, and prompts | What the run is intended to use | That remote model files are complete |
| `request.json` | Request for the current run | Run name and mode | That a stage completed successfully |
| `generation_audit.jsonl` | Teacher-generation attempts, parse results, and rejection reasons | Why a demonstration was retained or rejected | That all teacher reasoning is correct |
| `dataset/train.json` | Teacher demonstrations that actually enter training | Training examples and count | That the data has no bias or leakage |
| `dataset/dataset_info.json` | Training-data source and summary | Where the training data came from and how it was formed | Conclusions beyond the source-data license |
| `eval_dev/before_predictions.jsonl` | Per-question output from the original student | Concrete pre-training behavior | Full benchmark capability |
| `eval_dev/before_summary.json` | Aggregate pre-training settings and metrics | A same-protocol `before` summary | Post-distillation effectiveness |
| `train_config.yaml` | Actual LoRA training configuration | Model, data, rank, alpha, targets, and steps | That the configuration is appropriate or training succeeded |
| `train.log` | Training-process log | Progress, loss, errors, and duration | That decreasing loss means higher answer accuracy |
| `train_complete.json` | Training-stage completion record | Completion state, configuration fingerprint, and duration | That an exported model can be loaded |
| `adapter/` or `adapter-lite/` | LoRA incremental parameters and configuration | That the incremental artifact exists | That it works without the matching base model |
| `export_config.yaml` | Merge/export configuration | How the adapter and base are combined | That the merge completed |
| `merged_manifest.json` | File list and hashes for the merged model | Which files belong to the export | Model-generation quality |
| `merged/` | Reloadable combined student model | That the export artifact exists | That evaluation completed |
| `eval_dev/student_predictions.jsonl` | Per-question output from the trained student | Qualitative same-question comparison with `before` | That a few examples represent overall performance |
| `eval_dev/student_summary.json` | Post-training development summary | Same-protocol student metrics | The teacher upper bound or final-test result |
| `environment/process-*/supervisor.json` | Inference subprocess exit and cleanup state | Whether a process ended cleanly | That the model answer is correct |
| `frozen.json` | Configuration and file fingerprints frozen before the final test | Whether the pre-test contract was locked | That the test set was never used in earlier work |

## Commonly confused terms

- **gold:** the dataset's reference final answer, used to check teacher or student output.
- **teacher_text:** the complete text generated by the teacher model; it may still be wrong.
- **adapter:** the incremental weights learned by LoRA; small, but dependent on the matching base model.
- **merged:** the complete reloadable model after the adapter has been combined with the student base.
