# 固定镜像，按能力与当前阶段判断

用于解释或处理旧镜像与新课程包的差异。目标是保住已经可用的运行环境，不是让所有版本号、路径和检查计数都与文档一样；也不是把真实错误改写成 PASS。

本原则的“固定镜像不重装”适用于镜像路线，不阻止用户在自己的新机器上按约定搭建隔离环境。本机 Windows、macOS、Linux 的路线选择见 [local-compute.md](local-compute.md)。先区分控制端和计算端；改用新后端需要适配实际执行代码，不能仅删除 CUDA/BF16 检查就认定兼容。分别记录文档支持、局部测试和全链实测状态。

## 三层分开更新

| 层 | 本课程策略 |
|---|---|
| 镜像运行环境：CUDA、Torch、生成环境、训练环境 | 复用，不因课程包升级自动重装、升级依赖或重制镜像 |
| 课程代码/文档/登记接口 | 由 Coach 引导取得配套版本，放独立 live 目录，验证后选择；保留镜像内旧代码 |
| 模型/数据/run/manifest | 保留原位置与来源，不随代码升级重新下载、重建或覆盖 |

`/root/train-env` 可能是 editable 安装，实际 `llamafactory` 源码仍在旧 `/root/distill-course/vendor/LLaMA-Factory`。新课程脚本调用这个已验证 CLI 是正常情况，不要求源码搬到 live 目录，更不能删掉旧目录导致现有训练环境失效。

## 先问“影响当前哪一步”

| 观察 | 默认判断 | 下一步 |
|---|---|---|
| Python/依赖补丁版本、GPU 名称、路径不同 | 记录差异，不自动失败 | 用已选解释器和当前阶段 import/加载/运行证据判断 |
| 没有 `.git`，但可信 bundle 文件完整 | 可用的分发方式 | 记录 bundle 哈希，不强行重建 Git 仓库 |
| 模型已齐，ModelScope/HF/PyPI 某站不通 | 警告，仅影响依赖该站的新下载/安装 | 继续本地文件讲解/推理/训练；需要下载时检查实际备援来源 |
| runs/data 在数据盘、不随镜像保存 | 持久化提醒，不是运行失败 | 说明释放前保存/备份；不强制迁盘 |
| `pip check` 有不相关 Web/UI 包冲突 | 风险提示，不自动重装 | 看是否落在当前调用依赖链；相关 import/执行失败才修复 |
| 新课程包的 README 等文件哈希变化 | 包身份差异，不是 CUDA 损坏 | 对照预期发布版本/本地修改；不随手重写哈希来消警 |
| 新包出现未知代码改动、缺文件或真实 CPU 功能测试失败 | 暂不选用受影响的新包/功能 | 保留旧包与环境，修复/换已验证包；不扩散为整机不可用 |
| 教师还在下载，学生已完整 | 教师相关阶段待就绪，不是全局失败 | 可做学生独立加载检查、文件/视频讲解；不伪造 run 前置产物 |
| 模型哈希不符、分片缺失、tokenizer 真正不能加载 | 阻断对应模型阶段 | 定位具体文件，保留日志；不默认重下两个模型 |
| CUDA/必要算子失败、选定精度不可用、实际 OOM | 阻断当前 GPU 配置 | 修复具体能力或经用户同意调整资源配置；CPU 教学仍可继续 |
| 正式评测协议/数据不同、test 未冻结 | 阻断相应正式比较或测试 | 不以“环境宽容”为由放宽结果真实性 |

同一次检查可报告“当前 smoke 可继续，网络下载不可用，训练环境尚待验证”，而不是一个全局红绿灯。输出至少说明：现象、影响的阶段、现有证据、能继续的工作、需要修复的具体项目。不要把用户对风险的确认当成模型校验通过；也不要把没读过文档当作执行失败。

## 更新课程包后的最小复核

1. 核对新包自身身份与实际 CLI，尤其外部模型登记接口；这一步在大型下载之前做。
2. 确认仍使用原来的生成解释器与 `COURSE_TRAIN_ENV`，做必要 import 和 CLI 检查；已可用时不调用安装/依赖重新求解脚本。
3. 对比旧包/新包的 `configs/course.json` 与资产格式。只改文档/课程脚本、配置字节不变，不应导致重新准备数据。`data_ready` 目前仍保存整个配置文件哈希：若确有差异，先查语义，不把旧数据直接判成损坏；需要配置迁移时单独处理并保留来源，不手改旧 manifest 或冻结 run 来绕过检查。
4. 登记完成后复用资产。代码变更只影响哪些能力，就复核哪些能力；登记接口变更先测本地登记/校验，推理/训练行为变更再用新 run 验证受影响阶段。备课发布仍应完成一次端到端 smoke；每次课堂开始不必重装、重下或重跑所有正式实验。

`setup_env.py ...` 的 dry-run 是安装计划，不是既有环境的健康证明；网络/当前包源解析失败不能证明原环境坏了，train 计划甚至可能获取 vendor 源码。只有排查出必要能力缺失且用户同意修复时再用它。

## 限制说清楚

旧镜像不需要更新，但新课程接口仍需通过真正可取得的课程包交付。Skill 的文字更新不会让旧脚本自动获得新命令；未发布的本地修改不能说成已可从 GitHub 拉取。版本获取见 [repository-sync.md](repository-sync.md)。
